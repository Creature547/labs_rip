# Лабораторная 4 — JWT и активные сессии Redis

Сохранены существующие API, JWT и blacklist. Добавлена серверная сессия:
при входе создаётся случайный session_id, в Redis записывается
`session:<session_id> = anna_lab4` с TTL 3600 секунд. Идентификатор передаётся
клиенту в cookie `session_id`; cookie имеет HttpOnly и SameSite=Lax.
Secure включается при HTTPS. Полный JWT в Redis не хранится.

## Установка поверх текущего проекта

1. Остановить Go-сервер сочетанием Ctrl+C в его терминале.
2. Распаковать содержимое папки awesomeProject поверх текущей папки проекта
   с заменой файлов. Существующий `.env` сохранить: он не включён в этот ZIP.
   Ничего не удалять в Docker и PostgreSQL; миграция БД не требуется.
3. В терминале, находясь в папке с go.mod, выполнить:

```bash
go test ./...
go run ./cmd/awesomeProject
```

Новых зависимостей нет. PostgreSQL, Redis и MinIO должны быть запущены.

## Вход и скрин 8

1. Открыть Swagger в инкогнито по работающему IP и порту 8080:
   `/swagger/index.html`.
2. Вызвать POST `/api/users/auth` с существующей учётной записью:
   `{"login":"anna_lab4","password":"lab4pass"}`.
3. Получить HTTP 200. Сервер устанавливает cookie session_id и возвращает JWT.
4. ДО ВЫХОДА открыть новый терминал VS Code и выполнить:

```bash
docker exec -it heating_redis redis-cli
```

Внутри redis-cli:

```text
SCAN 0 MATCH session:* COUNT 100
```

Скопировать полный ключ из ответа. Если SCAN вернул ненулевой курсор,
повторить SCAN с этим курсором до получения нужного ключа или курсора 0.
В командах ниже заменить `session:ID` именно скопированным ключом:

```text
GET session:ID
TTL session:ID
```

GET должен показать `anna_lab4`, TTL — положительное число секунд.
Это новый скрин 8. Увеличить шрифт терминала и захватить команды и ответы.
Подпись: «Рисунок 8 — Активная сессия пользователя в Redis».
Старые ключи blacklist могут существовать до истечения TTL; удалять их не нужно.

## Postman с белой галочкой

Импортировать `postman/Lab4_sessions.postman_collection.json`.
В переменной коллекции base_url указать тот же IP и порт, что у Swagger,
например `http://172.31.200.120:8080` (IP может измениться).

Для входа через Swagger открыть инструменты браузера F12 → Application →
Cookies → адрес сервера. Скопировать значение session_id и записать в
переменную коллекции session_id. При входе через Postman переменная
заполняется автоматически из Set-Cookie.

В защищённых запросах уже установлен Authorization → No Auth, а в Headers
вручную добавлен `Cookie: session_id={{session_id}}` с переключаемой галочкой.
Автоматическая отправка cookie из Cookie Jar отключена в настройках запросов:
это позволяет честно показывать гостя снятием галочки. Для PUT гостем используйте
отдельный запрос «Проверка: публикация гостем — 401»; он не передаёт cookie.

Показ: один и тот же PUT публикации без Cookie → 401, с действующей Cookie → 200.
Нужен собственный существующий черновик и его ID в equipment_id.
Для скринов 4–5 список опубликованных приборов возвращается с cookie и без неё.

Исходная коллекция `Lab4.postman_collection.json` тоже обновлена: JWT передаётся
ручным заголовком Authorization с белой галочкой. Выберите одну коллекцию
для показа; API-маршруты у них одинаковые. Обе содержат 13 сценариев.

## Что делает выход

POST `/api/users/logout` принимает cookie сессии или JWT.
Он удаляет текущую сессию и очищает cookie. При передаче JWT дополнительно
добавляет его jti в blacklist. Выданный при этом входе JWT связан с сессией,
поэтому удаление сессии прекращает доступ и через этот JWT.
При наличии явного Authorization сервер проверяет его и не переключается
на cookie при ошибке. Другие активные сессии пользователя сохраняются.
Публичный список и лента остаются доступными гостю.

Важно: после входа в Swagger браузер автоматически отправляет cookie.
Поэтому гостевые проверки выполняйте в Postman с отключённым Cookie Jar,
как настроено в комплектной коллекции.
